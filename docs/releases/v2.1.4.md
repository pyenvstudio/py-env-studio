# Py Env Studio 2.1.4

## Project Environment Association & Runtime Mismatch Guard

Py Env Studio 2.1.4 introduces **Project Environment Association** and a conservative **Runtime Mismatch Guard** to make environment drift visible without taking control away from the developer or competing with IDE environment management.

### Highlights

- **Project ↔ Environment Association**
  - Project-based environment creation now includes an association option.
  - Association is enabled by default.
  - The project and generated environment are shown during creation.
  - Users can decline the association and create an unregistered environment.

- **Project Environment Management**
  - Added a project environment panel under the **Project** menu.
  - View the environment currently associated with a project.
  - Change the association to another existing PES environment.
  - Unregister an environment without deleting it.

- **Runtime Mismatch Detection**
  - PES now compares the project's registered environment with the runtime it can reliably observe.
  - Matching runtimes remain silent.
  - Mismatches are surfaced through PES runtime workflows.
  - `pes status` now reports the runtime/association state.
  - `pes on` and `pes run` warn once for an unchanged mismatch to avoid notification spam.

- **Conservative Runtime Detection**
  - PES only reports runtime information it can actually observe.
  - It does not attempt to infer which interpreter VS Code or PyCharm has selected.
  - It does not automatically switch IDE interpreters.
  - No IDE extension is required for this release.

### Example

When the project and runtime agree:

```text
Project: my-api

Registered Environment:
  my-api-abc123
  Python 3.12.4

Runtime:
  Python 3.12.4

Status: MATCH
```

When a mismatch is detected:

```text
Environment mismatch detected

Project:
  my-api

Registered Environment:
  my-api-abc123

Current Runtime:
  Global Python

[Use PES Environment] [Keep Current]
```

The warning is informational and does not prevent the developer from intentionally using another environment.

## Persistence

No SQLite schema changes were introduced.

The project/environment association uses the existing:

- `pes.config`
- project registry
- existing PES persistence mechanisms

Runtime notification suppression is also stored through the existing configuration mechanism.

No new database or metadata fields were introduced for MCP.

- Existing MCP tools
- MCP tool behavior
- Package-manager behavior
- Environment lifecycle behavior
- IDE interpreter configuration
- Existing project/environment workflows outside the new association capability

Existing projects without an associated environment continue to work normally.

## Architecture

The feature intentionally remains in the PES core:

```text
Project
   │
   ▼
Registered Environment
   │
   ▼
Runtime Detection
   │
   ▼
Mismatch Detection
   │
   ├── pes status
   ├── pes on
   └── pes run
```

Future IDE integrations can provide IDE-specific interpreter information later, but this release does not depend on them.

## Why This Feature

A project can be associated with one environment while commands are executed through another runtime. This can lead to confusing dependency, testing, and reproducibility problems.

Py Env Studio 2.1.4 makes this state visible while preserving developer control:

> **PES reports the mismatch; the developer decides what to do.**

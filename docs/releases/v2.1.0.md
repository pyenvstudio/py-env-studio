# Release Notes: v2.1.0

Released September 23, 2026.

Version 2.1.0 is the largest Py Env Studio release so far. It adds a project
factory (templates), a centralized configuration center, official Python
Install Manager runtime integration, vulnerability remediation from the
dashboard, and a new **beta** MCP control plane that lets AI coding agents
read authoritative environment state from Py Env Studio.

## Highlights

- 🧪 **New (beta): MCP control plane** — local, read-only, stdio MCP server for
  VS Code Copilot and other MCP clients, with 8 tools and a project
  intelligence report.
- 🧩 **Project templates** — built-in Python Script / CLI / Package templates,
  user templates from a local folder or GitHub, and GitHub Community Templates
  discovery.
- ⚙️ **Configuration center** — one dialog for default venv path, default
  Python, package manager, project tool, template defaults, appearance, UI
  scaling, and runtime provider.
- 🐍 **Official Python Install Manager integration** — detect, list, install,
  and select official Python runtimes from the runtime provider layer.
- 🛡️ **Vulnerability remediation** — `Update Now` per vulnerability and
  `Upgrade all Packages` per environment, with partial-failure reporting.
- 📊 **Native dashboard charts** — severity and trend charts are now native
  `tkinter-dash` widgets; `matplotlib` is no longer a dependency.
- 📶 **Informative progress** — a CLI progress gauge, a GUI status bar gauge,
  and verbosity controls (`-v` / `-q` / `--no-progress`).
- 📄 **Project contract foundation** — portable `pes.config` declared contract
  plus the `project_contract` SQLite table.

## 🧪 Beta feature: MCP control plane

MCP (Model Context Protocol) support ships in **beta**. Py Env Studio is the
infrastructure, not the model: Copilot (or any MCP client) does the reasoning,
while PES returns authoritative environment, package, dependency, security,
runtime, and project facts.

```text
MCP client (Copilot / agent)  →  MCP (stdio, local-first)  →  Py Env Studio Core
```

Beta scope:

- **Read-only.** No tool creates, changes, or deletes environments and no tool
  installs, upgrades, or removes packages.
- **Local stdio only.** No HTTP transport, no network calls, no remote access.
- **No MCP-triggered scans.** `pyenv_scan_vulnerabilities` returns the cached
  scan that PES already produced; PES itself owns network scanning.
- **Opt-out and rename** through the `[mcp]` section of `config.ini`.

Because this is a beta, tool names, schemas, and response envelopes can change
in a future minor release until the interface is marked stable. Setup steps for
VS Code and other clients are documented in
[the MCP reference](../reference/mcp.md).

## 🧩 Project factory: templates

- **Built-in templates** — Python Script, Python CLI, and Python Package
  (src-layout with tests), available directly from the **Templates** menu.
- **Guided creation wizard** — preview the generated structure, optionally
  create the virtual environment, install dependencies, and initialize Git,
  then open the project with a detected or preferred editor.
- **Manage Templates** — save your own project as a template, import from a
  GitHub repository URL, and delete user templates with confirmation.
- **Community Templates** — search public GitHub repositories, preview them
  through static inspection, and import a result as a reusable template.
  Repository code is never executed during discovery, preview, or import.
- **Non-blocking creation** — the window reports creation state, success, and
  failure while work runs off the UI thread.
- **Plugin hook** — successful creations emit `after_template_created`.

See [Templates Phase 1](../project-templates/phase-1.md),
[Templates Phase 1.2](../project-templates/phase-1-2.md), and
[Community Templates](../project-templates/community-templates.md).

## ⚙️ Configuration center (Tools → Configuration)

The new configuration dialog centralizes preferences and validates them before
saving:

- Default virtual-environment path and default Python interpreter/runtime
- Default package manager (`pip` / `uv`, with availability checks)
- Default project tool plus configurable **Open with** tools
- Template project defaults (create virtual environment, initialize Git)
- Appearance mode (Light / Dark / System) and UI scaling
- Runtime provider selection (Python Install Manager / System / Custom)
- Apply, Save, Cancel, and Reset-to-defaults flows with runtime refresh

## 🐍 Python runtime management

- Official **Python Install Manager** provider: detect the tool, list installed
  runtimes, list available official versions, install a runtime, and select it
  for environment creation.
- **System** and **Custom** provider options, prefix-aware version matching,
  and asynchronous, async-safe runtime loading states in the GUI.
- Cached runtime metadata (per provider/version plus freshness/error state) in
  SQLite; a failed online refresh never replaces cached rows.

## 🛡️ Security and remediation

- **Scan Now** and the **Vulnerability Report** dashboard remain the entry
  points, and remediation now happens in place.
- **Update Now** upgrades a single vulnerable package to the
  remediation-recommended fixed version after confirmation, marks the finding
  as fixed, and refreshes the report.
- **Upgrade all Packages** plans the highest recommended fix per affected
  package, reports partial failures, and refreshes resolved statuses.
- Remediation is disabled when no fixed version exists or the installed version
  already satisfies the recommendation.

## 📊 Dashboard, status, and logging

- Severity and trend charts in the Vulnerability Insights dashboard are native
  `tkinter-dash` widgets that follow the active appearance mode (Light/Dark).
- The **status bar** shows the current activity with a determinate gauge for
  known step counts and a marquee for unknown durations; the gauge disappears
  when no task is running.
- Every application window now shows the Py Env Studio icon, including dialogs
  and the insights dashboard.
- Rotating log file (`py_env_studio.log` in the platform data directory) for
  every action, with warnings and errors mirrored to the console.

## ⌨️ CLI

- `py-env-studio mcp` starts the beta MCP server on stdio.
- A single-line **progress gauge** for long-running commands (`--create`,
  `--install`, `--uninstall`, `--import-reqs`), drawn only when stderr is a
  TTY; piped/redirected output stays clean.
- Shared output controls before or after the command: `-v/--verbose`,
  `-q/--quiet`, `--no-progress`, plus `PES_LOG_LEVEL`, `PES_NO_PROGRESS`, and
  `PES_PROGRESS`.
- Failures print one `ERROR <component>: …` line on stderr, keep the full
  traceback in the log file, and exit with status `1`.

See the [CLI reference](../getting-started/cli.md).

## 🔧 Platform, packaging, and stability

- Freeze/PyInstaller stability refactor using Python 3.12+ language features,
  shared tool probing, and safer cross-thread UI scheduling.
- All SQL definitions are centralized as templates under `core/schema/*.sql` and
  executed in file order by `DatabaseManager.initialize_database`.
- `matplotlib` was removed in favour of `tkinter-dash`; the PyInstaller specs
  bundle the icon resources and `tkinter_dash`.
- `pip`/`uv` routing keeps its automatic pip fallback, and AutoResolver keeps
  recovering from dependency-resolution failures.

## Upgrade

```bash
pip install --upgrade py-env-studio
```

- Python 3.12 or newer is required.
- Existing user configuration, environments, user templates, plugins, and the
  SQLite database are kept; new preference keys are added with defaults.
- The MCP server is enabled by default but only runs when a client launches
  `py-env-studio mcp`. Set `enabled = false` in the `config.ini` `[mcp]`
  section to refuse startup.

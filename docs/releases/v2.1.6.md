# Release Notes: v2.1.6

Py Env Studio 2.1.6 expands the existing explicitly triggered vulnerability
scan into a package-level vulnerability intelligence history. It continues to
use the existing scanner, SQLite database, and Vulnerability Insights dashboard.

## Vulnerability Intelligence History

- Each successful OSV query records timestamped advisory observations without
  overwriting earlier scans. Repeated identical advisory IDs in one query are
  stored once; CVE/GHSA aliases are grouped in profile counts while original
  source records and aliases remain available for traceability.
- Advisory publication, modification, and withdrawal dates are kept distinct
  from PES collection times. The dashboard shows year-by-year disclosure
  counts, zero-count years between recorded disclosures, severity summaries,
  affected/fixed release details, source links, and changes since a previous
  successful scan when a valid comparison exists.
- CVSS vectors, scoring versions, OSV attribution, and CWE identifiers are
  retained. Conflicting severity values across aliased source records are
  labeled as conflicting rather than silently combined. Pattern categories
  use structured CWE data only; records without supported CWE data are shown
  as unknown or unclassified.
- The existing dependency view now uses deps.dev's resolved graph nodes and
  edges to label direct and transitive findings and show a representative
  parent path. Graph-resolution warnings and the generic-platform limitation
  are surfaced in the dashboard.
- Successful empty scans, failed API calls, and partial graph/API scans remain
  distinct. An advisory omitted from a later API result is not marked fixed.

## Collection and data limitations

- External requests still occur only when a user explicitly starts a scan; no
  polling or scheduled requests were added. Identical source/package/version
  requests are coalesced within one scan. A new explicit scan queries current
  source data so API changes can be observed.
- OSV's version query returns advisories matching the queried package version;
  it is not a complete catalog of every advisory ever published for every
  release. Historical charts therefore describe the evidence PES has collected
  for scanned versions, not proof that an unlisted year or version was safe.
- Disclosure dates, affected release lists, CVSS, CWE data, and withdrawn
  status are shown only when supplied by OSV. Affected ranges are retained even
  when an exact release count cannot be derived.
- deps.dev resolves a generic platform graph; it can differ from the actual
  environment's installed graph. PES displays available edges and API warnings
  rather than claiming an exact local transitive dependency tree.
- PyPI 2.1.5 was published before its GitHub release/tag were withdrawn. That
  version cannot be replaced on PyPI; this full-scope release uses 2.1.6.

## Validation

The focused vulnerability-history/profile, dashboard-chart, schema-template and
migration, MCP server, and MCP consistency run passed **64 tests**. The changed
Python modules passed `compileall`. The test run emitted existing Python 3.12
SQLite datetime-adapter, `importlib.resources`, app-icon and requests dependency
warnings.
